01 · Executive Summary & Core Questions ​

Enterprise AI applications—such as rubric-scoring / control-evaluation agents and multi-node document-review workflows—assemble multi-thousand-token prompts combining system policies, skill catalogs, tool schemas, workspace context cards, and retrieved grounding evidence. Migrating these workloads from gpt-4.x or o3-mini to GPT-5.6, GPT-6, and GPT-6.1 without explicit prefix engineering causes cache misses, a 2.56× spike in deployed PTU draw (170 → 435 PTUs at the 5-PTU increment; 2.60× raw TPM), higher time-to-first-token (TTFT) latency, and unamortized cache-write charges.

  1. Prompt caching remains active on GPT-5.6+, introducing an explicit control surface (prompt_cache_key, prompt_cache_options, prompt_cache_breakpoint), TTL-tiered cache-write billing (12h billed from November 1, 2026), and a default reasoning.context = "all_turns" setting on GPT-5.6 and GPT-6 that amplifies multi-turn token volume [M].
  2. Deployment SKU dictates available controls: Explicit breakpoints work on Standard 5.6+ and PTU-M GPT-6+, whereas GPT-5.6 on PTU-M does not support breakpoints and relies on strict prefix ordering + prompt_cache_key [M].
  3. In a stateless web backend (Model 2), Azure KV caching is the only cross-turn hydration cache: Dynamic fields injected early by middleware (e.g., live timestamps or user IDs) silently zero out cache hits.
  4. Caching readiness belongs inside the 7-layer quality gate alongside accuracy and safety checks so model-retirement waves never degrade production capacity or latency.

02 · Stateless Agent Runtimes & the Hydration Tax ​

Production enterprise agent platforms follow a Model 2 stateless web backend pattern (constructed and torn down on every HTTP request) rather than a Model 1 stateful local CLI process (resident in memory across turns) [Arch]. Each turn hydrates T0 (global static policies, skills, sorted tool schemas, domain methodology), L2 (workspace/case context card), and L1 (user persona and append-only session checkpoints), transmitting the full prompt over the wire.

03 · KV-Tensor Mechanics & GPT-5.6+ Delta ​

Azure OpenAI evaluates the rendered prefix in strict wire order: (1) structured outputs schema (response_format), (2) system / developer messages, (3) tools[] definitions, and (4) conversation messages & multimodal blocks [M]. Every cache hit requires >=1,024 identical leading tokens; the legacy 128-token rounding on <=5.5 no longer applies on GPT-5.6+.

05 · Cache Write/Read Break-Even Economics & Node Archetypes ​

For a reusable prefix P >= 1,024 tokens written once (w_write = 1.25) and read k subsequent times within its TTL (w_read = 0.10 on GPT-6, 0.05 on gpt-6.1-sol), effective weight per prefix token is C(k) = (1.25 + k × w_read) ÷ (k + 1):

  • k = 0 (One-shot miss): 1.25x (+25% penalty) → disable caching via prompt_cache_options: {"mode":"explicit"} with zero breakpoints.
  • k = 1 (Single reuse): 0.675x on GPT-6 / 0.650x on 6.1-sol (−32.5% to −35% net) → break-even is reached on the very first cache read.
  • k = 10 (Production gate SLO [Agree]): 0.205x on GPT-6 / 0.159x on 6.1-sol (−79.5% to −84.1% net).

06 · Scope × Volatility Prefix Order & Middleware Refactoring ​

Keep {"role": "system"} + sorted tools[] 100% Global T0 so tools[] caches across all workspaces and users, and inject L2 (workspace) and L1 (user) as a leading developer context message ahead of append-only *history:

python
import json


def build_messages_cache_ready(
    static_policy: str,
    domain_methodology: str,
    l2_workspace_card: dict,
    l1_persona_card: dict,
    history: list[dict],
    rag_chunks: str,
    query: str,
    supports_explicit_breakpoints: bool,  # True on Standard 5.6+ & PTU-M GPT-6+; False on PTU-M GPT-5.6
):
    t0_block = {"type": "text", "text": f"{static_policy}\n\n{domain_methodology}"}      # Pos 1 & 3 (Global T0 >= 1,024t)
    l2_block = {"type": "text", "text": json.dumps(l2_workspace_card, sort_keys=True)}   # Pos 4 (shared per scope_id)
    l1_block = {"type": "text", "text": json.dumps(l1_persona_card, sort_keys=True)}     # Pos 5a (shared per user_id)

    if supports_explicit_breakpoints:
        t0_block["prompt_cache_breakpoint"] = {"mode": "explicit"}  # Breakpoint #1: global T0 + tools[] reuse
        l2_block["prompt_cache_breakpoint"] = {"mode": "explicit"}  # Breakpoint #2: workspace-wide L2 reuse

    return [
        {"role": "system", "content": [t0_block]},
        {"role": "developer", "content": [l2_block, l1_block]},
        *history,
        {"role": "user", "content": f"<retrieved_grounding>\n{rag_chunks}\n</retrieved_grounding>\n\n{query}"},
    ]

07 · Wire Controls, >15 RPM Sharding & APIM Spillover ​

  • Deterministic Sharded Key ([M] + [Arch]): Format keys as {app}:{node_or_skill}:{prompt_ver}:shard-{0..N-1} where N = max(1, ceil(Peak_RPM / 12)), routing turns via hash(thread_id) % N so per-key traffic stays below the ~15 RPM partition threshold without embedding user_id or uuid4().
  • Breakpoint Budgets ([M]): Up to 4 new cache writes/request (3 explicit + 1 automatic latest-message write in implicit mode; 4 explicit in explicit mode) and 50 read candidates across history.
  • APIM SKU-Aware Spillover ([Arch]): Size base PTU-M below ~60–70% saturation; preserve prompt_cache_key across both legs; strip unsupported prompt_cache_breakpoint / prompt_cache_options fields when forwarding to a GPT-5.6 PTU-M backend while keeping them intact on Standard spillover and GPT-6+ PTU-M; honor Retry-After on HTTP 429.

08 · 7-Layer Quality Pipeline, PCR001–006 & KQL Release Gate ​

  • Layer 1 (PR Static Lint): Run pcr_lint.py (PCR001 key/sharding, PCR002 Pos-1 volatile tokens, PCR003 unsorted json.dumps, PCR004 early RAG chunks, PCR005 invalid 5.6 PTU-M breakpoints / deprecated retention, PCR006 missing cached_tokens extraction across input_tokens_details and prompt_tokens_details).
  • Layer 2 & 3 (2-Pass Eval & Multi-Turn Replay): Warm cache on Pass 1; assert cached_tokens >= 1,024, cached share >=60%, steady-state hit rate >=80%, and Read/Write >= 10:1 [Agree] alongside output quality parity.
  • Layer 5 & 7 (Peak Load & OTel/KQL): Validate >15 RPM/family sharding under load and enforce the two-regime Application Insights KQL gate (separating coincident deployment-wide DeployPeakNormTPM from per-shard cache metrics):
kusto
// Application Insights KQL: Per-node cache efficiency + Two-Regime Shard & Deployment-Wide PTU Normalized TPM
// Last verified: 2026-11-18 21:21 PST | License: MIT
let AllCalls = AppDependencies
| where TimeGenerated > ago(24h) and Type == "AzureOpenAI"
| extend cd = parse_json(Properties)
| extend cache_key = tostring(cd["gen_ai.prompt_cache.key"]), node_name = tostring(cd["agent.node_name"]),
         model_name = tostring(cd["gen_ai.request.model"]), sku = tostring(cd["azure.deployment.sku"]),
         input_tok = tolong(cd["gen_ai.usage.input_tokens"]), output_tok = tolong(cd["gen_ai.usage.output_tokens"]),
         cached_tok = tolong(coalesce(cd["gen_ai.usage.cached_tokens"], 0)),
         write_tok = tolong(coalesce(cd["gen_ai.usage.cache_write_tokens"], 0)),
         ttft_ms = todouble(cd["gen_ai.latency.ttft_ms"])
| extend uncached_tok = max_of(input_tok - cached_tok - write_tok, 0)
| extend norm_tok = case(  // Short-context (<=272K) weights; use 2x input/cache & 7.5x output if input_tok > 272000
         model_name has "6.1", uncached_tok + 0.05 * cached_tok + 1.25 * write_tok + 5.0 * output_tok,
         model_name has "gpt-6", uncached_tok + 0.10 * cached_tok + 1.25 * write_tok + 5.0 * output_tok,
         (input_tok - cached_tok) + 6.0 * output_tok);  // Pre-GPT-6 (5.6 / 5.4): 0x cached, 6x output
let DeployPeak = AllCalls  // Includes <1,024-token & unkeyed calls that share the same PTU deployment
| summarize DeployMinuteTPM = sum(norm_tok) by model_name, sku, bin(TimeGenerated, 1m)
| summarize DeployPeakNormTPM = round(max(DeployMinuteTPM), 0), DeployP95NormTPM = round(percentile(DeployMinuteTPM, 95), 0)
         by model_name, sku;
let CacheCalls = AllCalls | where isnotempty(cache_key) and input_tok >= 1024;
let ShardPeak = CacheCalls
| summarize MinuteNormTPM = sum(norm_tok) by node_name, model_name, sku, cache_key, bin(TimeGenerated, 1m)
| summarize ShardPeakNormTPM = round(max(MinuteNormTPM), 0) by node_name, model_name, sku, cache_key;
CacheCalls
| summarize Calls = count(), HitRatePct = round(100.0 * countif(cached_tok > 0) / count(), 1),
            CachedSharePct = round(100.0 * sum(cached_tok) / max_of(sum(input_tok), 1), 1),
            ReadWriteRatio = iff(sum(write_tok) == 0, real(null), round(todouble(sum(cached_tok)) / sum(write_tok), 1)),
            TTFT_p95_ms = round(percentile(ttft_ms, 95), 0), ShardAvgNormTPM = round(sum(norm_tok) / 1440.0, 0)
         by node_name, model_name, sku, cache_key
| join kind=inner ShardPeak on node_name, model_name, sku, cache_key
| join kind=leftouter DeployPeak on model_name, sku
| extend GateStatus = iff(HitRatePct >= 80.0 and CachedSharePct >= 60.0
                          and (isnull(ReadWriteRatio) or ReadWriteRatio >= 10.0), "PASS", "FAIL")
| project-away node_name1, model_name1, sku1, cache_key1, model_name2, sku2
| order by GateStatus asc, DeployPeakNormTPM desc, ShardPeakNormTPM desc
