Why It Matters

Sizing a secondary DR deployment only for steady-state cached TPM causes immediate HTTP 429 throttling during a real regional failover because the secondary stamp's KV prefix cache starts completely cold (0% hit rate).

Key Takeaway

Account for the 1.8×–2.56× Cold-Cache Warm-Up Surge during the first 5–15 minutes of regional cutover, and absorb it elastically via Secondary Data-Zone/Regional Standard PAYG.

Practical Application

Run the interactive BCP & Cold-Cache Surge Advisor below to size primary PTUs, standby anchors, and secondary PAYG TPM quotas.

1. Quantifying the Cold-Cache Failover Surge [Arch] ​

From Playbook 01, a tuned multi-node document-review workload (100 RPM, 10,000 input tokens, 500 output tokens, 80% cached prefix share on gpt-5.6-terra) requires only 170 PTUs (500,000 Normalized TPM) in steady state because cached prefix tokens consume 0% PTU capacity (0.10x / 0.05x on GPT-6 / 6.1) [M].

When Primary Region A suffers an outage and APIM switches 100% of live traffic to Secondary Region B:

  • Minute 0–2 (Cold Secondary KV Cache, 0% Hit Rate): Every shard (shard-0..8) must write and compute full prefix tensors (1.0x on 5.6, 1.25x write weight on 6/6.1). Normalized TPM temporarily spikes to 1,300,000–1,450,000 TPM (435–485 PTU equivalent — 2.56×+)!
  • Minute 3–10 (T0 Shards Warm, L2 Warming): Practice-wide T0 shards reach 100% hit parity within 1–2 turns per shard; engagement-scoped L2 prefixes warm across active sessions.
  • Minute 15+ (Steady Secondary Equilibrium): Cache hit rate stabilizes back at ~80%, returning capacity draw to the 170 PTU baseline.

3. Interactive Multi-Region BCP & Surge Calculator ​

The advisor blocks metrics, recommendations, and Markdown export for blank, non-finite, or out-of-range numeric inputs instead of silently clamping them. Primary capacity must be a safe whole number of at least 15 PTUs in 5-PTU steps; cached share accepts 0–95%, including fractional percentages. Surge capacity and combined reservations must also remain safe integers. These are local estimator guardrails, not a universal Azure SKU availability or scale-increment guarantee. Field-linked errors clear after correction, and valid inputs preserve the existing posture math. Offline interaction regressions run in npm run verify; they do not certify quota, throughput, RTO, or live failover readiness [Arch].
