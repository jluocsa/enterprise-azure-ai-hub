Why It Matters

Secondary DR stamps rot silently when primary deployments upgrade model snapshots, rotate RBAC roles, or outgrow secondary PAYG TPM quotas.

Key Takeaway

Run automated daily snapshot-parity probes plus a 30-minute quarterly Game-Day cutover drill verified by the B1–B12 BCP Readiness Standard.

Practical Application

Execute the 5-step Game-Day runbook below in non-peak windows and archive the KQL telemetry output for compliance sign-off.

1. Five-Step Quarterly Game-Day Drill Protocol [Validate] ​

  1. Pre-Flight Drift Check (T - 15 min): Verify identical model name, version snapshot string, content-filter policy name, APIM Managed Identity RBAC (Cognitive Services OpenAI User), and Secondary AI Search document count parity (≤1% delta).
  2. Synthetic Canary Cutover (T + 0 min): Apply an APIM inbound test header (x-bcp-drill: force-secondary) or trip Priority-1 health status for a 10% canary slice, then ramp to 100% traffic onto Secondary Stamp B.
  3. Cold-Cache Surge Observation (T + 0..15 min): Run bcp-failover-readiness-gate.kql to measure:
    • Cutover RTO (time from primary 503/429 injection to first HTTP 200 on Secondary Stamp B).
    • Cold-cache peak TPM absorbed without surfacing HTTP 429 to end users.
    • Time for Secondary CachedSharePct to climb from 0% above 60%.
  4. Stateful Turn Continuity Test (T + 15 min): Start a multi-turn agent thread in Stamp A, force mid-conversation failover to Stamp B, upload/query a grounded document, and verify zero Cosmos DB checkpoint loss and valid AI Search citations.
  5. Failback & Evidence Sign-Off (T + 30 min): Restore Priority-1 routing to Stamp A, verify automatic circuit-breaker healing, and export the KQL drill record for Risk/Audit retention.

Snapshot Evidence Must Include the Expected Secondary ​

A per-region healthy KQL row cannot prove cross-region parity: two regions can each report one different snapshot, and a silent secondary emits no row at all. Before B2/B11 sign-off, run the offline snapshot companion gate on the drill's exported KQL result objects against an independently approved model/region manifest. It requires positive call evidence from every expected region and an exact match to the pinned snapshot, rejecting unknown snapshots, duplicates, and unexpected stamps [Arch].

Manifest rows accept only reqModel, stampRegion, expectedSnapshot, and optional metadata; unsupported fields block sign-off with exit 2 before evidence is read. Keep annotations inside metadata and set freshness via --max-age-minutes. Metadata does not enforce content-filter, capacity, or other readiness controls, and extra KQL evidence columns remain supported. See the manifest contract and offline regressions. This is a local fail-closed configuration policy, not an Azure service limit [Arch].

Region identity is case-insensitive in both the manifest and evidence: eastus and EASTUS represent one region, not independent primary and secondary stamps. Casing aliases are rejected as duplicates, while casing differences alone do not reject otherwise complete evidence. Model and snapshot identities remain exact. This local normalization does not resolve display-name aliases or validate region availability; use approved region identifiers [Arch].

Send synthetic probes to the standby during the selected lookback window; absence of secondary evidence must block sign-off, not count as a healthy standby. Snapshot success does not validate content-filter parity or replace the live failover and stateful-continuity checks above [Validate].

Freshness must be checked per stamp: an active primary must not hide an old secondary observation or a replayed export. The companion requires the updated query's LastSeen timestamp and rejects missing, timezone-less, future, or stale values [Arch]. Its default maximum age is 15 minutes, configurable with a positive integer --max-age-minutes to match the approved probe cadence; this is a local readiness threshold, not an Azure guarantee [Agree].

Fresh traffic must also include successful inference, not just recent failures. The updated query exports SuccessfulCalls and LastSuccessfulSeen from instrumented model dependencies with HTTP 200–299; the companion requires a positive successful-call count no greater than TotalCalls and applies the same freshness limit to the last successful call. A standby returning only errors, or recent failures after an old success, must block snapshot sign-off. Regenerate older exports rather than substituting LastSeen for LastSuccessfulSeen [Arch]. HTTP 2xx alone does not establish completed streaming output, stateful continuity, or the full readiness standard; keep the live drill checks [Validate].

An expected-stamp manifest or evidence export that exceeds the JSON parser's nesting limit must block sign-off as an input-integrity failure (2), not an ordinary snapshot mismatch (1). The companion emits a sanitized diagnostic without a traceback or partial success; ordinary nested metadata remains supported. See the kit's parsing boundaries and offline regressions. This is a local readiness policy, not an Azure nesting limit [Arch].

Unreadable manifest or evidence files (missing files, directories, permission/I/O failures, or invalid UTF-8) also exit 2 with a fixed stderr diagnostic, no stdout, and no traceback. Paths and operating-system/decoding details are not copied into CI logs; inspect the supplied artifacts in restricted storage. Neither input-read failure can produce partial snapshot sign-off. See the kit's offline failure/recovery regressions; this local reporting policy does not sanitize source artifacts or authenticate evidence [Arch].

Unquoted NaN, Infinity, and -Infinity in either input also block sign-off with exit 2, even inside otherwise ignored metadata after valid stamp rows. The companion emits a fixed diagnostic without echoing input values; quoted strings and ordinary JSON metadata remain supported. See the kit's parsing boundaries and offline regressions. This local JSON-integrity policy does not validate metadata semantics, impose a numeric range on standard JSON numbers, or authenticate the export [Arch].

The last successful call cannot be later than the last call of any status in the same model/region aggregate. Even if both timestamps are fresh, LastSuccessfulSeen > LastSeen blocks snapshot sign-off with exit 1; equal instants remain valid after timezone normalization. Re-export inconsistent telemetry rather than widening the freshness window or editing timestamps to force a pass. This local consistency check does not authenticate evidence or replace the live drill [Arch].

If SuccessfulCalls == TotalCalls, the last successful call must also be the last call: different LastSuccessfulSeen and LastSeen instants block sign-off with exit 1. Equivalent timezone offsets remain valid, and mixed-success aggregates may retain an earlier last success. See the companion's aggregate-consistency contract and offline regressions. This local input-consistency rule neither requires all calls to succeed nor authenticates the exported telemetry [Arch].
