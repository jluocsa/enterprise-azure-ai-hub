Why It Matters

Enterprise CISOs block AI launches not because the LLM fails benchmarks, but because RAG pipelines strip Purview sensitivity labels, expose overshared sites, or leave revoked user permissions active in vector indexes for hours.

Key Takeaway

Enable Microsoft Purview DSPM for AI across Microsoft Foundry and Fabric, propagate sensitivity labels and Entra acl_group_ids immutably into every index and Cosmos DB document, and replace nightly crawlers with event-driven ACL tombstoning.

Practical Application

Review the Purview DSPM control plane and 3-tier revocation SLA architecture below with CISO, Risk, and Compliance leads.

1. Microsoft Purview DSPM for AI Across Foundry & Fabric [M] ​

Microsoft Purview Data Security Posture Management (DSPM) for AI provides unified visibility and compliance governance over both Microsoft Foundry applications and Microsoft Fabric / Copilot in Fabric workloads [M]. Rather than bolting on bespoke regex loggers after launch, activate four foundational Purview controls before ingesting production data (Gate D4):

  1. Oversharing Assessments Before Indexing: Run Purview DSPM oversharing discovery across SharePoint, OneDrive, and OneLake repositories prior to connecting Azure AI Search indexers or Fabric Data Agents—remediating overly broad "Everyone except external users" links before an agent amplifies them [M] [Arch].
  2. Sensitivity Labels & Inheritance: Apply organizational Microsoft Purview sensitivity labels (Public, Internal, Confidential, Highly Confidential / Ethical-Wall) across OneLake items, Power BI Semantic Models, and source documents. When labeled data is referenced in Fabric or Foundry interactions, Purview tracks label inheritance and prevents unauthorized users from accessing restricted sources [M].
  3. Foundry Interaction Capture, Audit & eDiscovery: Configure Purview collection policies for Microsoft Foundry to capture AI prompts, responses, and sensitive information types (SITs) into Purview Audit, Communication Compliance, and eDiscovery—while keeping application-level OpenTelemetry spans strictly metadata-only (OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=false per Playbook 04 Gate A12) [M] [Arch].
  4. Data Loss Prevention (DLP) & Insider Risk Policies: Block sensitive data types (credentials, regulated client identifiers, unapproved PII) from leaking into unsanctioned prompts or external connectors [M].

2. End-to-End Label & Entra ACL Propagation Contract [Arch] ​

A critical vulnerability occurs when ingestion jobs extract text with Azure AI Content Understanding and write plain JSON chunks to Azure AI Search or Azure Cosmos DB without carrying forward source authorization metadata. Every indexed record must carry an immutable security envelope (Gate D5):

3. Event-Driven ACL Revocation & Tombstoning SLA (Gate D6) ​

In regulated assurance, legal, M&A, and financial platforms, access revocation speed is an audit-blocking requirement. Suppose an analyst is moved off Engagement A onto competing Engagement B (an ethical wall trigger) at 09:00 UTC. If Azure AI Search or Cosmos DB relies on a nightly 24-hour full re-crawl to refresh acl_group_ids, the analyst retains retrieval access for up to 24 hours.
