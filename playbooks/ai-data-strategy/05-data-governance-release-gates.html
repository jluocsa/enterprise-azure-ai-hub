Why It Matters

Data governance standards written only in slide decks break down as soon as teams add a new SharePoint connector, change an embedding model, or onboard a new tenant without checking Purview labels and ACL tombstoning.

Key Takeaway

Enforce the 12-point D1–D12 standard in every release pipeline using the zero-dependency data_readiness_gate.py CLI (DRG001–DRG007) and monitor live drift with data-grounding-freshness-gate.kql.

Practical Application

Wire data_readiness_gate.py into PR / pre-cutover pipelines and include D1–D12 in the Architecture Review Board sign-off checklist.

2. Deterministic CI Verification: data_readiness_gate.py (DRG001–DRG007) ​

The MIT-licensed, zero-dependency Python 3 CLI (docs/public/kits/data_readiness_gate.py) validates an exported data-plane snapshot JSON against a contract exported from the Interactive Data Strategy Advisor.

Rule Reference & Fail-Closed Exit Semantics ​

  • Exit 0 (PASS): Every declared dataset/corpus passed all configured DRG001–DRG007 contracts.
  • Exit 1 (BLOCKED — Gate Violation): Valid JSON inputs violated one or more readiness rules (DRG001–DRG007).
  • Exit 2 (BLOCKED — Invalid Input / Contract): Unreadable file, invalid UTF-8, duplicate JSON object keys (including nested objects), unquoted non-standard numeric constants, excessive JSON nesting, malformed/unknown top-level contract fields, or contradictory threshold bounds—never silently downgraded to defaults [Arch].
Rule IDDeterministic Check Enforced
DRG001Snapshot schema integrity, non-empty datasets[], unique source_id entries, optional exact expected_source_ids inventory, explicit types/booleans, finite numeric bounds.
DRG002Fabric / OneLake lineage (medallion_tier in gold/ai-gold, non-empty source_uri, and exactly 64 ASCII hexadecimal characters in lineage_sha256), valid store_target (fabric-iq, ai-search, cosmos-hybrid), and dedicated_interactive_fsku=true when fabric-iq is enabled.
DRG003Microsoft Purview DSPM for AI active (purview_dspm_enabled=true), valid non-empty sensitivity_label on every dataset, and zero restricted datasets (Confidential / Highly Confidential) marked allow_public_index=true.
DRG004Entra ACL enforcement (acl_enforced=true), non-empty acl_group_ids on non-public datasets, revocation_lag_minutes <= max_revocation_lag_min (15 enterprise / 5 regulated), and zero overdue tombstones (overdue_tombstones == 0).
DRG005Store-specific production parity: cosmos-hybrid requires vector_index_type in {"diskANN", "quantizedFlat", "flat"}, hybrid_rrf_enabled=true, tenant_partition_key_scoped=true, and consistent positive-integer embedding_dim within the selected index limit (flat: 505; quantizedFlat/diskANN: 4096); ai-search requires alias_cutover_enabled=true and region_lag_pct <= max_region_lag_pct.
DRG006Corpus hygiene & anti-poisoning: avg_chunk_tokens within [min_chunk_tokens, max_chunk_tokens], duplicate_or_empty_ratio_pct <= max_duplicate_ratio_pct, and zero indirect prompt-injection signatures in sample_chunks[].
DRG007Grounding freshness & cache-safe flywheel: freshness_lag_minutes <= max_freshness_lag_min, pos6_cache_safe_ordering=true, and eval_flywheel_enabled=true when required by contract.
bash
# Run offline self-test suite (zero external dependencies)
python3 docs/public/kits/data_readiness_gate.py --self-test

# Evaluate a pre-cutover data-plane snapshot against a Decision Studio contract
python3 docs/public/kits/data_readiness_gate.py ./artifacts/data-snapshot.json \
  --contract ./data-readiness-contract.json --json

Strict JSON Numeric Constants (DRG001) ​

Both the acceptance contract and data snapshot reject unquoted NaN, Infinity, and -Infinity anywhere, including ignored root metadata and metadata in a later dataset after otherwise valid evidence. These inputs exit 2 before snapshot evaluation, with no stdout or partial readiness report. The diagnostic identifies the input role without echoing paths, member names, or constant values. Invalid contract JSON is rejected before the snapshot file is read [Arch].

Quoted strings such as "NaN", ordinary JSON scalars, and nested metadata remain supported. This is a local JSON-integrity policy, not a Microsoft service requirement, metadata-schema validator, or evidence-authenticity check. Standard JSON numbers that overflow floating-point parsing are not rejected by this constant rule; existing finite-number checks still apply to enforced numeric fields [Arch].

Offline regressions exercise all three constants in enforced fields and ignored nested metadata for both inputs, text/JSON CLI exit 2, contract-before-snapshot validation, and exit 0 recovery with valid metadata. They run through node scripts/run-python.mjs docs/public/kits/data_readiness_gate.py --self-test in npm run verify, without live Azure access [Validate].

Approved Dataset Inventory (DRG001) ​

An optional expected_source_ids contract field blocks a clean subset or substituted corpus from passing readiness. required_stores checks store coverage, not dataset completeness: several required corpora can share the same store. Approve the inventory independently of the submitted snapshot [Arch].

json
{
  "expected_source_ids": [
    "fabric-finance-kpis",
    "search-regulatory-corpus",
    "cosmos-agent-episodic-memory"
  ]
}

Every expected identifier must appear exactly once, with no unexpected identifiers; matching is exact and case-sensitive, and dataset order is irrelevant. Existing duplicate-source checks remain active. Missing or unexpected sources produce DRG001 and exit 1, preserving other findings and dataset counts. Inventory diagnostics use counts and dataset ordinals, never the missing or unexpected identifier values [Arch].

The field must be a non-empty array of unique, non-empty strings without leading or trailing whitespace. Invalid inventories exit 2 with no stdout before snapshot evidence is read. Omission preserves existing defaults and Decision Studio exports; null and empty arrays do not disable the check. This local acceptance contract verifies declared inventory completeness, not artifact authenticity, live connector access, or source-content quality [Arch].

The kit's offline self-test covers reordered complete snapshots, omitted and substituted datasets, duplicate entries, combined governance failures, and invalid inventory types in text and JSON CLI modes. It runs through node scripts/run-python.mjs docs/public/kits/data_readiness_gate.py --self-test in npm run verify [Validate].

Lineage Digest Syntax (DRG002) ​

Every dataset, across all three store targets, must supply lineage_sha256 as exactly 64 ASCII hexadecimal characters (0–9, a–f, A–F). Lowercase, uppercase, and mixed-case digests are accepted without normalization. Missing values, non-string types, placeholders, incorrect lengths, non-hex characters, and surrounding or embedded whitespace produce DRG002 and exit 1; other findings and dataset counts remain intact. The diagnostic identifies the dataset ordinal and field without echoing the digest or source identifier [Arch].

This is a local lineage-metadata syntax contract, not a Microsoft service requirement. Generate the digest from an independently defined lineage artifact and retain that artifact for review: the gate does not recompute hashes, authenticate provenance, compare approved lineage pins, or prove zero-copy ingestion. A syntactically valid fabricated or stale digest can still pass [Arch].

Offline self-tests cover missing and malformed values for every store, valid casing and recovery, combined governance failures, and text/JSON CLI exit codes with non-echoing diagnostics. Existing sample snapshots and Decision Studio contract exports remain compatible. These regressions run in npm run verify, without accessing live Fabric, Search, or Cosmos resources [Validate].

Cosmos Vector Index Dimension Limits (DRG005) ​

Azure Cosmos DB for NoSQL supports at most 505 dimensions for flat vector indexes and 4,096 dimensions for quantizedFlat and diskANN, according to the published vector-index limits [M].

For each cosmos-hybrid dataset, DRG005 requires a positive integer embedding_dim no greater than the selected index's limit. A flat index with 1536 or 3072 dimensions therefore blocks readiness even though those are valid Decision Studio sizing presets. Oversized dimensions exit 1, with dataset ordinals rather than source identifiers in the new diagnostic; other findings and cross-dataset dimension consistency checks remain active. Fabric and AI Search datasets are unaffected [Arch].

This offline metadata check does not inspect the deployed container policy, vector lengths, embedding-model compatibility, or retrieval recall. Choose a compatible index and embedding model before creating the container; passing this check does not prove live deployment readiness [Arch].

Self-tests cover each index's inclusive upper boundary, one dimension above it, small valid dimensions, incompatible flat presets, malformed index types, combined governance/parity failures, and text/JSON CLI exit codes. They run through node scripts/run-python.mjs docs/public/kits/data_readiness_gate.py --self-test in npm run verify, without live Azure access [Validate].

3. Continuous Production Drift Monitoring (data-grounding-freshness-gate.kql) ​

Deploy data-grounding-freshness-gate.kql into Log Analytics / Application Insights to detect post-cutover regressions before users report stale answers:

  • Ingestion & ACL Tombstoning Lag (D6, D11): Alerts when MaxRevocationLagMin > 15 (> 5 regulated) or MaxFreshnessLagMin > 60.
  • Purview DSPM Label Coverage (D4, D5): Fails immediately if UnlabelledRetrievalCount > 0.
  • Cosmos DB Hybrid RU & Fabric CU Throttling (D3, D7): Tracks Cosmos429RatePct, p95 RU charge per hybrid query (flagging accidental cross-partition fan-out), and Fabric IQ 429/CU delay events.
  • Zero-Grounding Drift (D12): Surfaces rising empty-retrieval rates so missing OneLake shortcuts or broken indexers trigger automated alerting.
