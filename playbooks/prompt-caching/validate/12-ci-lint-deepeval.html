12 · Automated CI Scanner (PCR001–006) & DeepEval Gate ​

1 · Start2 · Qualify & Size3 · Design4 · Validate5 · Govern
3 min readVerified 2026-11-19 PST
Why It Matters

Even after a clean migration, a routine pull request adding a timestamp to system instructions can silently break caching in production.

Key Takeaway

Block regressions in PR CI with two fast gates: zero-dependency static linting (pcr_lint.py) + a 2-pass DeepEval cache-hit assertion.

Practical Application

Add pcr_lint.py to repository CI during Week 1 to surface prefix-breaking defects automatically on every pull request.

Prevent un-cached code from promoting by enforcing two automated checks in pull-request CI: (1) static AST/regex linting (PCR001–PCR006) in Layer 1, and (2) a 2-pass DeepEval quality + cache-hit contract test in Layer 2 [Arch].

1. Layer 1: Static Codebase Scanner Rule Catalog (PCR001–PCR006) ​

Preview and copy the full zero-dependency CLI scanner on the Copy-Ready Engineering Kits page (or download pcr_lint.py directly: python3 pcr_lint.py ./src).

The scanner fails closed with PCR000 and exit code 1 for missing/inaccessible targets, unsupported explicit files, directories with no eligible sources, unreadable/non-UTF-8 files, or invalid Python syntax. Directory scans exclude generated/dependency folders such as node_modules and .venv, and the linter itself; a clean file does not mask another target's failure. --json includes these diagnostics in the same finding array as readiness defects [Arch]. This validates scan integrity, not TypeScript/JavaScript/C# syntax or runtime cache behavior; retain native build checks and Layer 2 probes.

Python AST recursion failures also block the scan with a file-level PCR000 at line 1, whether triggered by parsing deeply nested source or rendering an expression for a readiness check. Other files and targets are still scanned, with their findings retained in text/JSON output and no traceback. The offline self-test exercises both phases and actual deep-source CLI inputs; the linter does not evaluate expressions or increase the interpreter's recursion limit [Arch].

The PCR001 constant check is a local routing readiness policy applied to matching Python calls regardless of model, not an Azure API requirement. It inspects only AST constants without evaluating source expressions; computed keys still need runtime assertions, and non-Python key validation is outside this check's scope [Arch].

2. Layer 2: Unified DeepEval Quality + 2-Pass Cache Contract Test ​

Illustrative CI pattern normalizing usage fields across both the Responses API (input_tokens / input_tokens_details) and Chat Completions API (prompt_tokens / prompt_tokens_details):

python
import pytest
from deepeval import assert_test
from deepeval.test_case import LLMTestCase
from deepeval.metrics import GEval


def _extract_cache_usage(resp) -> tuple[int, int, str]:
    """Normalize usage & text across Responses API (/v1/responses) and Chat Completions."""
    u = resp.usage
    input_tok = getattr(u, "input_tokens", None) or getattr(u, "prompt_tokens", 0)
    details = getattr(u, "input_tokens_details", None) or getattr(u, "prompt_tokens_details", None)
    cached_tok = getattr(details, "cached_tokens", 0) or 0
    text = getattr(resp, "output_text", None) or resp.choices[0].message.content
    return input_tok, cached_tok, text


# Illustrative — bind invoke_node() and golden_cases (sharing >=1,024-token Pos 1-4 prefix) to your app client
@pytest.mark.parametrize("model", ["gpt-5.4", "gpt-5.6-prod-ptu"])
def test_node_migration_quality_and_cache_gate(model, golden_cases):
    """Layer 2 Gate: Verifies GEval accuracy AND 2-pass prompt cache hit rate on GPT-5.6+."""
    case_a, case_b = golden_cases[0], golden_cases[1]  # Distinct Pos 6 inputs sharing identical Pos 1-4 prefix

    # Pass 1: Cold/warm write call with deterministic family+version+shard key
    r1 = invoke_node(case_a["input"], model=model, prompt_cache_key="doc-review:summarizer:v12:shard-0")
    # Pass 2: Second case with identical static/workspace prefix (Pos 1-4) and different dynamic tail (Pos 6)
    r2 = invoke_node(case_b["input"], model=model, prompt_cache_key="doc-review:summarizer:v12:shard-0")

    _, _, out_a = _extract_cache_usage(r1)
    input_tok_b, cached_tokens, _ = _extract_cache_usage(r2)
    assert cached_tokens >= 1024, f"[{model}] Expected cache hit >= 1024 tokens on Pass 2, got {cached_tokens}"
    assert (cached_tokens / max(input_tok_b, 1)) >= 0.60, "Cached input share fell below 60% gate"
    # Assert steady-state Read/Write ratio (>= 10:1) across the full 50-200 case replay aggregate (Ch. 11 Step 5)

    assert_test(
        LLMTestCase(input=case_a["input"], actual_output=out_a, expected_output=case_a["expected"]),
        [GEval(name="Correctness", criteria="Accurately conveys expected domain findings", threshold=0.8)],
    )
