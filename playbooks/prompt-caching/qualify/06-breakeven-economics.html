06 · Cache Write vs. Cache Read Break-Even Economics ​

1 · Start2 · Qualify & Size3 · Design4 · Validate5 · Govern
3 min readVerified 2026-11-19 PST
Why It Matters

GPT-5.6+ cache-write fees (1.25× weight) raise questions about whether prompt caching could cost more than uncached calls.

Key Takeaway

Just ONE subsequent cache read (1:1 ratio) already cuts effective prefix cost by 32.5%–35%; at a 10:1 target gate, cost drops by 80%–84%.

Practical Application

Use the break-even curve below to verify that write penalties occur only when early dynamic text forces repeated 0:1 misses.

Because GPT-5.6, GPT-6, and GPT-6.1 introduce explicit cache-write billing (including 12h write billing effective November 1, 2026) and normalized PTU weights [M], architecture teams must verify that cached prefixes are read enough times within their TTL to amortize the initial write premium.

Mathematical Break-Even Formula [M] ​

For a reusable prefix of P >= 1,024 tokens written once at short-context (<=272K) normalized weight w_write = 1.25 and read k subsequent times within its TTL at weight w_read (0.10 on GPT-6, 0.05 on gpt-6.1-sol), the effective normalized weight per prefix token across k + 1 total requests is:

text
C(k) = (1.25 + k × w_read) ÷ (k + 1)

FinOps Takeaway

Break-even requires only one subsequent read (k = 1) on 30m TTL. Cache-write regressions occur only when early volatile tokens (such as timestamps in Pos 1) force k = 0 on every request—turning every call into an unamortized 1.25x write.
