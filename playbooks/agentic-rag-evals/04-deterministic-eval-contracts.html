Why It Matters

Gating pull requests solely on LLM-as-judge 1–5 rubric scores introduces non-deterministic CI flakiness, judge prompt-injection blind spots, and high PR latency.

Key Takeaway

Enforce the Golden Separation Rule: Deterministic checks gate merges; calibrated LLM judges score semantic quality trends and flag edge cases for human review.

Practical Application

Adopt the two-tier evaluation matrix below and wire agent_release_gate.py into GitHub Actions / Azure Pipelines.

Fail-Closed Trace Evidence (ARG001) ​

[Arch] Every non-blank JSONL line must be a complete turn object. Missing evidence must block release rather than silently defaulting token counts to zero or omitting a turn from the latency sample.

Required fieldTrace contract
case_id, statusNon-empty strings; terminal status must be "ok".
assistant_responseString; an empty answer is structurally valid, not proof of semantic quality.
tools_called, retrieved_doc_idsArrays of non-empty strings; use [] when no tools/documents were involved.
pass_numberInteger >=1; booleans, numeric strings, and fractional values are rejected.
input_tokens, cached_tokensIntegers >=0, with cached_tokens <= input_tokens.
duration_msFinite number >=0 for every turn; missing values, NaN, and infinities are rejected.
acl_trimmedExplicit boolean required on non-empty retrievals when ACL enforcement is enabled; false triggers ARG006.
raw_prompt_loggedExplicit boolean required when metadata-only telemetry enforcement is enabled; true triggers ARG007.
otel_capture_message_contentOptional; must be a boolean when present and triggers ARG007 when true under metadata-only enforcement.

All supplied ACL/privacy flags must be booleans even when their enforcement is disabled. Structurally invalid turns produce ARG001 failures and exit 1 (including under --json); malformed JSON produces a line-numbered ARG001 error on stderr and exit 2. Diagnostics for malformed evidence identify the row/field without echoing raw turn content. The zero-dependency python3 docs/public/kits/agent_release_gate.py --self-test regression suite is included in npm run verify.

Missing/unreadable trace files, directory inputs, and invalid UTF-8 also exit 2 with a sanitized ARG001 stderr diagnostic and no stdout in text or --json mode. The CLI reads the complete file before evaluating any turns, so a valid prefix followed by undecodable bytes cannot produce a partial pass. Read-error diagnostics omit paths, file content, and operating-system exception details; self-tests cover file/encoding failures and injected permission/I/O errors without relying on platform-specific file permissions [Arch].

Unambiguous JSON Inputs ​

[Arch] Trace records and acceptance-contract files must use unique member names within every JSON object, including optional nested metadata. The CLI rejects duplicates before schema validation or evaluation instead of silently keeping the last value: "raw_prompt_logged": true followed by "raw_prompt_logged": false must not turn failing evidence into a pass. Identical duplicate values are also rejected, and JSON escape sequences are decoded before comparing names.

Duplicate trace members produce a line-numbered ARG001 stderr diagnostic; duplicate contract members produce an invalid-acceptance-contract stderr diagnostic. Both exit 2 with no stdout, including under --json, without echoing member names or values. Reusing a name in separate objects or separate JSONL records remains valid. This is a local input-integrity rule, not an Azure service requirement or proof that exported evidence is authentic; preserve trusted trace provenance.

JSON exceeding the Python parser's nesting limit also exits 2 without a traceback or stdout in text and --json modes. Trace diagnostics identify the physical JSONL line (ARG001); contract diagnostics identify invalid acceptance configuration before trace evidence is read. Neither echoes nested member names, values, or exception details, and a valid trace prefix cannot produce a partial pass. Offline CLI regressions cover deeply nested arrays and objects in both inputs, plus ordinary nested metadata that remains valid. This handles parser recursion failures, not a fixed portable depth budget, file-size limit, memory-exhaustion guard, or evidence-authenticity check [Arch].

Fail-Closed Citation Syntax (ARG003) ​

[Arch] Every literal, case-sensitive [cite: opener in assistant_response must form a complete [cite:ID] marker. IDs must contain one or more ASCII letters, digits, or _ . : # - characters (no spaces). Empty IDs, whitespace, unsupported characters, nested markers, and missing closing brackets produce ARG003 and exit 1, including under --json, rather than disappearing from the resolution check. Malformed-marker diagnostics do not echo the answer or malformed ID; well-formed IDs still must exactly match retrieved_doc_ids.

Repeated valid markers remain allowed. Answers without citation markers remain structurally valid: this gate verifies marker syntax and ID resolution, not citation completeness, source relevance, or whether the cited document supports the answer. Keep those semantic checks in the calibrated quality review above.

Fail-Closed Acceptance Configuration ​

[Arch] The CLI validates acceptance configuration before reading trace evidence, without coercing strings, booleans, or fractional token thresholds. Invalid configuration exits 2 with a field-specific stderr diagnostic and no success-shaped JSON output, including under --json.

Contract fieldAccepted configuration
max_p95_msFinite number >0; numeric strings, booleans, NaN, and infinities are rejected.
min_pass2_cached_tokensInteger >0; no strings, booleans, or fractional values.
required_tools, forbidden_toolsArrays of non-empty strings, not a single string; [] explicitly disables that list.
require_acl_trimming, forbid_raw_prompt_loggingExplicit JSON booleans; "false", 0, and null are invalid.

The contract root must be a JSON object. Omitted fields retain existing defaults (15000 ms, 1024 cached tokens, the built-in forbidden tools, no required tools, and both ACL/privacy controls enabled); Studio metadata such as contract_version and track remains compatible. CLI-only --max-p95-ms and --min-cached-tokens obey the same positive-threshold rules; --contract continues to take precedence over those flags. Missing/unreadable files, invalid UTF-8, and malformed JSON also exit 2 without a traceback. These checks validate configuration integrity, not whether an explicitly chosen threshold is an appropriate release SLO [Agree].

Unknown top-level fields are rejected before trace evidence is read: misspellings such as required_tool or max_p95_mss must not silently substitute default governance or latency settings. Only the six enforcement fields above and the informational fields contract_version, track, and metadata are accepted. Informational fields do not configure enforcement; nested metadata remains extensible (and still obeys the unique-member rule). Move custom annotations into metadata rather than adding top-level fields. Unsupported fields exit 2 with no stdout in text or --json mode; diagnostics list supported names without echoing unknown names or values. This is a local configuration-integrity policy, not an Azure service schema, and does not certify that the chosen controls cover every release requirement [Arch].
