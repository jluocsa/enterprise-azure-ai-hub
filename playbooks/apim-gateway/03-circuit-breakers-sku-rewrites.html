Why It Matters

Custom C# retry loops inside APIM policies do not share state across gateway workers and fail when GPT-5.6 PTU-M rejects explicit cache breakpoint fields.

Key Takeaway

Use declarative APIM Backend Pools + Backend Circuit Breakers with acceptRetryAfter=true, authenticate via Managed Identity, and strip unsupported 5.6 breakpoint fields on the PTU leg.

Practical Application

Use the Bicep backend-pool definition and interactive policy generator below to produce deployment-ready gateway artifacts.

1. Declarative Backend Pool + Retry-After Circuit Breaker [M] ​

Azure API Management natively supports priority and weighted backend pools paired with backend circuit breakers that trip automatically on HTTP 429 or 5xx responses and honor upstream Retry-After headers [M]:

bicep
resource ptuBackend 'Microsoft.ApiManagement/service/backends@2024-05-01' = {
  parent: apimService
  name: 'foundry-ptu-primary'
  properties: {
    url: 'https://${foundryPrimaryName}.openai.azure.com/openai'
    protocol: 'http'
    circuitBreaker: {
      rules: [
        {
          name: 'ptu-throttle-or-5xx-breaker'
          failureCondition: {
            count: 1
            interval: 'PT10S'
            statusCodeRanges: [
              { min: 429, max: 429 }
              { min: 500, max: 599 }
            ]
          }
          tripDuration: 'PT30S'
          acceptRetryAfter: true
        }
      ]
    }
  }
}

resource paygBackend 'Microsoft.ApiManagement/service/backends@2024-05-01' = {
  parent: apimService
  name: 'foundry-standard-spillover'
  properties: {
    url: 'https://${foundrySpilloverName}.openai.azure.com/openai'
    protocol: 'http'
  }
}

resource foundryPool 'Microsoft.ApiManagement/service/backends@2024-05-01' = {
  parent: apimService
  name: 'foundry-ptu-with-payg-spillover-pool'
  properties: {
    type: 'Pool'
    pool: {
      services: [
        { id: ptuBackend.id, priority: 1, weight: 100 }
        { id: paygBackend.id, priority: 2, weight: 100 }
      ]
    }
  }
}

Why count: 1 + acceptRetryAfter: true Matters for PTU-M ​

When a PTU-M deployment crosses its normalized TPM saturation ceiling, Azure OpenAI returns HTTP 429 with an explicit Retry-After or x-ratelimit-reset-tokens window [M]. Tripping the Priority-1 backend immediately for that Retry-After window prevents hundreds of concurrent agent calls from wasting round-trips against a saturated PTU pool before spilling to Priority-2 Standard PAYG [Arch].

3. Interactive APIM Policy Generator ​

Configure your target model regime, spillover behavior, and FinOps governance below to generate ready-to-deploy APIM policy XML (or download the standalone kit from Engineering Kits):

Body-Safe Per-Attempt Routing ​

The generated policy and downloadable kit use explicit foundry-ptu-primary then foundry-standard-spillover backend IDs, defined above, rather than the mixed-SKU pool. A pool can select Standard on the first attempt when the PTU breaker is open; an inbound PTU-only rewrite would then strip Standard's fields too. Use the pool alternative only when all members accept the same body, or place a SKU-aware adapter behind it [Arch].

Capture the original request as a string before stripping fields. preserveContent: true preserves a body read, but returning a different body from set-body replaces the forwarded request; it does not save an original copy for retries (set-body reference) [M]. The retry block executes once before testing its retry condition (retry reference) [M]. Therefore, restore the saved string and select Standard only when a previous response is 429 or 503, before the second forward-request. This retains prompt_cache_options, nested breakpoints, and prompt_cache_key on the Standard leg without reserializing the original body. Keep request replay buffering enabled even when response streaming is disabled [Arch].

The PTU rewrite covers both Responses input[].content[] and Chat Completions messages[].content[]. Microsoft Learn documents breakpoint-bearing content blocks for both APIs, with GPT-5.6 breakpoint support limited to Standard rather than PTU-M [M]. The reference policy removes only top-level prompt_cache_options and each content block's prompt_cache_breakpoint; it leaves prompt_cache_key, text, multimodal payloads, tools, and other fields unchanged. Array/type guards leave string content and non-message input items alone, without recursively deleting similarly named fields in tool arguments or application data. The Studio's GPT-6 mode performs no inbound body rewrite [Arch].

The standalone kit assumes that foundry-ptu-primary is a GPT-5.6 PTU-M deployment and always applies its inbound rewrite. A caller's x-target-regime header does not change the configured backend and must not disable that backend's compatibility rewrite. For GPT-6/6.1, generate a separate policy using the Studio's target-regime control; this is deployment configuration, not a per-request routing selector. Standard retries still receive the original captured body [Arch].

npm run check:apim checks both the downloadable kit and rendered Studio default for XML syntax, a whitespace-normalized whitelist of the two-API PTU rewrite, its unconditional inbound placement, and the static routing/restoration contract. Mutation regressions reject conditional rewrites (including caller-header guards), missing API coverage, lost cache keys/content, missing field removal, missing/late snapshots, pooled routing, lost restoration, and unbuffered replay. The Studio interaction suite also checks generated/copied rewrite parity with the kit in both spillover modes and GPT-6 pass-through. These checks do not execute C# or certify live APIM behavior; intentional rewrite changes require updating the whitelist and reviewing the effective policy [Arch].

The set-body template="liquid" attribute selects Liquid templating rather than the policy's default body-expression mode [M]. Matching C# text alone therefore cannot establish that the PTU rewrite or Standard restoration runs as intended. The local gate requires both expression-bearing set-body elements to omit template entirely, rejecting Liquid, blank, computed, and unknown values. Offline regressions cover both expressions, recovery after removing the attribute, and exit 1 without a pass message for either kit or rendered-Studio Liquid mutations. This is a reference-artifact execution-mode contract, not a ban on Liquid elsewhere or a full APIM schema/C# validator; valid exports remain unchanged [Arch].

Keep forward-request's fail-on-error-status-code omitted (default false) or explicitly false. Setting it to true triggers on-error for HTTP 400–599, including 429 and 503; policy expressions are not allowed for this attribute [M]. That error path conflicts with this reference design's response-based retry and Standard body restoration. The local spillover gate rejects true, blank, computed, and unknown values in either the downloadable kit or rendered Studio default, with exit 1 and no pass message; omitted and literal false remain valid. Offline mutations cover rejection and recovery, not live gateway execution [Arch].

The set-variable policy assigns a named context variable and is available in all four policy sections [M]. The local gate therefore requires exactly one set-variable assignment to original-request-body across the entire document, not merely one direct inbound capture. A nested assignment after the PTU rewrite could replace the saved original with the stripped body while leaving the Standard restoration expression unchanged. Additional assignments are rejected regardless of section, branch condition, or value, including assignments before the capture and repeated identical expressions. Offline regressions cover both kit and rendered-Studio CLI inputs, exit 1 with no pass message, and recovery after removing the extra assignment; unrelated variable names remain allowed. This is a conservative single-write contract for these reference artifacts, not a C# interpreter or effective-policy analysis: inherited policies and other variable-writing policies still require review and live probes [Arch].

Before release, probe both API payload shapes with 429, 503, an already-open PTU breaker, and successful 200 streaming: confirm Standard receives the original cache fields, PTU receives the stripped body with the same cache key and content, and no retry occurs after stream headers. Include string content, multimodal blocks, and absent, GPT-6, or arbitrary x-target-regime header values; the header must not alter the fixed GPT-5.6 primary's rewrite. Transport/on-error failures are outside this response-based retry contract [Validate].

Keep Policy Output Variables Separate From the Saved Body ​

send-request writes a response object to response-variable-name; with ignore-error="true", a failed call can instead leave that variable null. authentication-managed-identity can write its string token to output-token-variable-name [M]. Neither write uses set-variable, so counting only explicit assignments cannot protect the saved request. A collision after capture can replace the original body with a response, null, or a token before Standard restoration [Arch].

The local gate rejects either policy when its output attribute is literally original-request-body, anywhere in the document, including nested authentication inside send-request. It conservatively rejects collisions before the snapshot and in inactive branches too, without evaluating ordering, conditions, or ignore-error. Rename the output to a separate variable rather than changing the body snapshot or restoration. Offline regressions cover both writers, before/after placement, true/false branches, both error-handling flags, kit and rendered-Studio CLI failures (exit 1, no pass message), and recovery by renaming the output; existing msi-access-token authentication remains unchanged [Arch].

This is a literal-name reference-artifact guard, not a full variable-write inventory or C# interpreter. Dynamic send-request output-name expressions, other output-writing policies, inherited policies, and runtime behavior still require effective-policy review and staging probes. Offline success does not certify live payload integrity [Validate].

No Unvetted Inbound Request-Body Reads ​

Microsoft Learn documents that context.Request.Body.As<T>() and AsFormUrlEncodedContent() use the original message stream by default and leave it unavailable after reading; preserveContent: true reads a copy instead (policy expression reference, IMessageBody) [M]. An extra inbound expression can therefore consume the body before the otherwise correct original-body snapshot or PTU rewrite runs.

The local gate permits direct context.Request.Body access only in the exact snapshot value and separately whitelisted PTU rewrite text. Extra references in inbound text or attributes, including nested branches and whitespace-separated member access, exit 1 without a pass message. The guard deliberately rejects even extra reads specifying preserveContent: true: these reference artifacts have only two reviewed request-body access sites. Header-only expressions remain allowed. Offline regressions cover both reading methods, explicit preservation flags, before/after placement, inactive branches, kit and rendered-Studio CLI failures, and recovery after removal [Arch].

This is a conservative textual guard, not a C# interpreter: it can also match references in string literals and does not resolve aliases, comments inserted between member names, inherited policies, or indirect access. Review the effective policy and run staging probes; offline success is not proof of live payload preservation [Validate].

No Unvetted Inbound Body Transformations ​

find-and-replace replaces request or response substrings; json-to-xml, xml-to-json, and xsl-transform also transform bodies and support inbound use [M]. An extra transformation before the snapshot can corrupt the saved Standard body even when the vetted PTU set-body and retry restoration remain intact; one after the rewrite can alter the PTU payload.

The local gate rejects all four policy tags anywhere under inbound, including nested branches before the snapshot or after the rewrite. It does not evaluate conditions or attributes to exempt apparently inactive or no-op transformations. Offline mutations exercise both positions, direct placement, true/false branches, kit and rendered-Studio CLI failures (exit 1, no pass message), and recovery after removing the transformation. Existing header, telemetry, routing, and vetted body policies remain unchanged. This conservative reference-artifact contract does not certify inherited policies, arbitrary C# body access, or live payload integrity; retain effective-policy review and the probes above [Arch].

Unambiguous Policy Sections ​

Microsoft Learn describes policy configuration as inbound, backend, outbound, and on-error sections (policy configuration reference) [M]. The published kit and Studio default use all four sections in that order. Their offline gate now requires exactly that root structure before checking any body, routing, or streaming policies: a duplicate section must not hide policies from first-section XML lookups. Missing, duplicate, reordered, or unexpected root elements exit 1 with a section-contract diagnostic and no pass message. Mutation regressions cover every section, including duplicate sections containing body replacements or authorization-header overrides, in both kit and rendered-Studio CLI inputs [Arch].

This is a local complete-document contract for these published artifacts, not a full APIM schema validator or a claim that every policy scope must contain all four sections. XML comments and formatting remain allowed, and existing valid generated policies are unchanged. Inherited policies, individual policy attributes, C# expressions, and live deployment still require effective-policy review and the probes above [Arch].

INTERACTIVE GATEWAY GENERATOR · PLAYBOOK 02SKU-Aware Azure API Management AI Gateway Policy Builder
<policies>
  <inbound>
    <base />
    <!-- 1. Passwordless Managed Identity Auth to Microsoft Foundry -->
    <authentication-managed-identity resource="https://cognitiveservices.azure.com" output-token-variable-name="msi-access-token" ignore-error="false" />
    <set-header name="Authorization" exists-action="override">
      <value>@("Bearer " + (string)context.Variables["msi-access-token"])</value>
    </set-header>
    <!-- 2. Out-of-Band FinOps Chargeback (Preserve Shared Prefix Cache Keys) -->
    <set-variable name="costCenter" value="@(context.Request.Headers.GetValueOrDefault(&quot;x-cost-center&quot;, &quot;unallocated&quot;))" />
    <set-header name="x-cost-center" exists-action="delete" />
    <!-- 3. Tenant / Practice Token Quota & OTel Metric Emission -->
    <azure-openai-emit-token-metric namespace="foundry-ai-gateway">
      <dimension name="SubscriptionId" value="@(context.Subscription.Id)" />
      <dimension name="CostCenter" value="@((string)context.Variables[&quot;costCenter&quot;])" />
    </azure-openai-emit-token-metric>
    <azure-openai-token-limit counter-key="@(context.Subscription.Id)" tokens-per-minute="450000" estimate-prompt-tokens="true" />
    <!-- 4. Snapshot the Original Body Before Any PTU-Only Rewrite -->
    <set-variable name="original-request-body" value="@(context.Request.Body.As&lt;string&gt;(preserveContent: true))" />
    <set-backend-service backend-id="foundry-ptu-primary" />
    <!-- 5. SKU-Aware Guard: Strip Unsupported Breakpoints on GPT-5.6 PTU-M Primary Leg -->
    <set-body>@{
      var body = context.Request.Body.As&lt;JObject&gt;(preserveContent: true);
      body.Remove("prompt_cache_options");
      foreach (var field in new [] { "input", "messages" }) {
        if (body[field] is JArray items) {
          foreach (var msg in items.OfType&lt;JObject&gt;()) {
            if (msg["content"] is JArray parts) {
              foreach (var part in parts.OfType&lt;JObject&gt;()) {
                part.Remove("prompt_cache_breakpoint");
              }
            }
          }
        }
      }
      return body.ToString(Newtonsoft.Json.Formatting.None);
    }</set-body>
  </inbound>
  <backend>
    <!-- Restore Original Body on Pre-Stream 429 / 503 Standard PAYG Retry -->
    <retry condition="@(context.Response != null &amp;&amp; (context.Response.StatusCode == 429 || context.Response.StatusCode == 503))" count="1" interval="1" first-fast-retry="true">
      <choose>
        <when condition="@(context.Response != null &amp;&amp; (context.Response.StatusCode == 429 || context.Response.StatusCode == 503))">
          <set-backend-service backend-id="foundry-standard-spillover" />
          <set-body>@((string)context.Variables["original-request-body"])</set-body>
        </when>
      </choose>
      <forward-request timeout="120" buffer-request-body="true" buffer-response="false" />
    </retry>
  </backend>
  <outbound>
    <base />
    <set-header name="x-gateway-routed-sku" exists-action="override">
      <value>@(context.Response.Headers.GetValueOrDefault("x-ms-deployment-name", "foundry-pool"))</value>
    </set-header>
  </outbound>
  <on-error>
    <base />
  </on-error>
</policies>
